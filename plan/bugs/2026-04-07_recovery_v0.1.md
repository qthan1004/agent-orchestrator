# BUG: Recovery falsely marks tasks as FAILED and leaves them dead in outbox

## Severity: CRITICAL ✅ FIXED

## Summary

The `RecoveryManager._handleStaleTask()` moves tasks to `outbox/` with `status: "failed"` when max retries exceeded. These failed tasks are **never recovered** — they stay dead in outbox forever, blocking the entire pipeline.

## Evidence

`exchange/outbox/result-01-scaffold.json`:
```json
{
  "task_id": "01-scaffold",
  "status": "failed",
  "summary": "Stale worker — exceeded max retries (3)",
  "worker_id": "w-97e3aebd"
}
```

## Root Causes & Fixes Applied

### 1. `_handleStaleTask` moved failed tasks to outbox (DEAD END)
- **File**: `src/mcp-server/recovery.mjs`
- **Was**: `moveToOutbox(taskId, { status: FAILED })` → task dies permanently
- **Fix**: ALWAYS `moveToInbox(taskId)` → task gets retried by new worker
- Retry counter resets after max exceeded → infinite recovery

### 2. `requeueOrphans` left tasks stuck in `active/` after max retries
- **File**: `src/mcp-server/recovery.mjs`
- **Was**: `continue` (skip task) → task stuck in active/ forever
- **Fix**: ALWAYS `moveToInbox(taskId)` regardless of retry count

### 3. `STALE_THRESHOLD_MS = 10s` too aggressive for agent workflows
- **File**: `src/constants.mjs`
- **Was**: 10_000 (10s) — agent tool calls take 10-30s+
- **Fix**: 120_000 (2 minutes)

### 4. `restoreFromFiles()` ignored failed tasks in outbox on startup
- **File**: `src/mcp-server/state-manager.mjs`
- **Was**: loaded outbox tasks as-is (FAILED stays FAILED)
- **Fix**: auto-detects FAILED tasks in outbox → moves them back to inbox with PENDING status

## Files Changed

| File | Change |
|------|--------|
| `src/mcp-server/recovery.mjs` | `_handleStaleTask` + `requeueOrphans` always requeue to inbox |
| `src/constants.mjs` | `STALE_THRESHOLD_MS` 10s → 120s, `MONITOR_INTERVAL_MS` 5s → 30s |
| `src/mcp-server/state-manager.mjs` | `restoreFromFiles()` auto-recovers FAILED tasks on startup |

## Verification

- All 3 modules import successfully ✅
- Constants verified: `STALE_THRESHOLD_MS: 120000`, `MONITOR_INTERVAL_MS: 30000` ✅
